title: Committees
description: The group of publishers that signs Lean Oracle's feeds.
---

A **committee** is a group of publishers that signs a basket of feeds. It is defined by a
`publisher_set_type` cell on CKB holding the publishers' public keys, the quorum rule and a set index.
Every feed cell records which committee it trusts, and your contract should check it.

Lean Oracle has one committee, `majors`. Each feed keeps its own methodology: the CKB pairs trade
more thinly, so they use wider windows and tolerances, but they tick with everything else. Pairs you
combine, like CKB/USDT and USDT/USD, come from the same update.

## majors

BTC, ETH and SOL in USD, USDT and USDC, USDT/USD, and CKB/USDT and CKB/USDC. One update per second.

## Quorum

A committee of `n` publishers needs `⌊2n/3⌋ + 1` signatures on each update: 3 of 4, 5 of 7, 7 of 9.
Up to nine publishers can join a committee. The target is seven.

<Callout type="warn" title="Testnet">
  The testnet committee currently has one publisher, so the quorum is 1 of 1. More independent
  publishers join before mainnet. See [Publishers](/docs/learn/publishers).
</Callout>

## When a committee changes

Keys change by rotating the committee cell, which a quorum of the current publishers must sign. The
type hash stays the same, so your contract keeps working. The set index goes up, and only updates
from the new set are accepted after that. See [Committee governance](/docs/operate/governance).
