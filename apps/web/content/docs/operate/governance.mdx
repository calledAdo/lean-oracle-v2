## Settings: the committee config

Everything except the keys lives in a versioned **committee config**: the feed list with IDs and
exponents, each feed's exchanges and minimum count, the methodology settings, and the tick timing.

1. Someone proposes a new version with an **activation tick**.
2. Each publisher reviews it and signs its hash. The config file collects the signatures.
3. With a quorum of signatures it is approved.
4. All publishers switch at the activation tick. Every signed update carries the active config's
   hash.

No transaction is needed. Adding a feed adds a leaf; removing one stops including it. Feed IDs are
never reused.

The tooling refuses configs that break the feed rules: a native pair on every listed market, at least
two exchanges required, one spare market, and each exchange at most once.

## Changing the committee cell

Every change to the committee cell is one **operation**, approved by a quorum of the current set.
The approval names the committee cell, so it is useless on any other committee. The cell has no owner
(an always-success lock): anyone may send an approved operation and no key can block one.

| Operation | Use it when | Also needs |
|---|---|---|
| `rotate` | adding, removing or replacing a publisher | proof of possession from every new key; the committee cell must be at least the committee's minimum interval old (24 hours by default) |
| `rotate-revoke` | keys are compromised | proof of possession; no waiting |
| `pause` / `unpause` | something is wrong and prices must stop | nothing else |
| `revoke-previous` | a retired publisher's key leaked after a rotation | nothing else |

- After a `rotate`, the previous set still verifies ticks **before** the new set's first tick, so
  integrators settling at an exact past time keep working. The minimum interval exists so that only
  one previous set is ever kept.
- `rotate-revoke` and `revoke-previous` drop the previous set at once.
- While paused, feed cells refuse updates and the consumer helpers treat stored prices as unusable.
- Committee cells can't be destroyed and never lose their CKB.

**The limit.** If a quorum of the current keys is stolen, the thief controls the committee and no
operation can take it back. Recovery is a new committee cell; integrators re-pin its type hash.

### Runbook

One coordinator (usually an existing publisher) prepares the operation; each operator signs on their
own machine with the publisher image. All commands below are `lean-oracle-publisher <command>`, run
as `docker run --rm -v $PWD:/w -w /w ghcr.io/calledado/lean-oracle-publisher:edge <command>`.
`<op>` is one of `rotate`, `rotate-revoke`, `pause`, `unpause`, `revoke-previous`; steps 5, 6 and 8 are
for rotations only.

| Step | Who | Command |
|---|---|---|
| 1. Read the current state | coordinator | `fetch-set --operator publisher.json > current.hex` |
| 2. Propose the next state | coordinator | `next-set --set current.hex --op <op> [--add <pubkey>] [--remove <pubkey>] [--until-ms <tick>] > next.hex` (a `rotate` needs `--until-ms`: the new set's first tick) |
| 3. Review | everyone | `show-set --set next.hex` |
| 4. Approve | a quorum of current members | `sign-governance --set current.hex --next next.hex --op <op> --operator publisher.json > auth-N.json` |
| 5. Prove possession | every next member | `sign-pop --next next.hex --operator publisher.json > pop-N.json` |
| 6. Re-approve configs | every next member | `sign-config --config configs/vN.json --key publisher.key --set next.hex > appr-N.json` |
| 7. Collect | coordinator | `merge-signatures auth-*.json > auth.json` (and `pop-*.json > pop.json`) |
| 8. Record config approvals | coordinator | `add-approval --file configs/vN.json --set next.hex appr-*.json`, then send the file to every operator |
| 9. Check | coordinator | `governance-status --set current.hex --next next.hex --op <op> --operator publisher.json --authorization auth.json [--pop pop.json]` |
| 10. Send | coordinator | `npm run govern:committee -w apps/deploy -- --network testnet --name majors --op <op> --next next.hex --authorization auth.json [--pop pop.json] --broadcast` |

After step 10, every publisher notices the change within 15 seconds, exits and restarts under it.

A `rotate` can be refused as "immature" for a minute or two after the interval has passed: the chain
measures the cell's age with block median time, which trails the clock. Send again.

`--operator publisher.json` signs with the key configured for that publisher (including AWS KMS)
and supplies the committee's type hash; with `--key <file>`, pass `--committee <type hash>`.

**Why step 6?** Publisher indexes follow the sorted list of keys, so they change when the set changes.
A config file carries each set's approval separately (`approvals`), so the configs are valid for the
new set the moment it goes live.

`--operator publisher.json` can replace `--key` wherever a signature is made, to sign with the key
configured for that publisher, including AWS KMS.
