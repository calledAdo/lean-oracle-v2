<Callout title="Onboarding">
  Testnet committees currently run with one publisher, and onboarding of independent operators is
  open. To start, run shadow mode (step 3) and open an issue on
  [GitHub](https://github.com/calledAdo/lean-oracle-v2/issues) with its report.
</Callout>

## What you commit to

- **Uptime.** Your publisher runs around the clock. A missing publisher weakens the quorum for
  everyone.
- **Independence.** Your own servers, network and exchange connections. Two publishers sharing
  infrastructure defeat the point of a committee.
- **Key custody.** Your signing key never leaves your control. It can live in a file or in AWS KMS.
- **Exchange terms.** You check each exchange's market-data terms for your jurisdiction.
- **Response.** Someone watches alerts and acts on them.

## What you need

- A Linux server (2 vCPU and 2 GB RAM are enough for one committee) with Docker.
- Network access to every exchange in the committee's configs. Binance and Bybit refuse US IP
  addresses; some ISPs block exchange domains.
- A public address for the peer port (7700) and a private one for the API port (7701), which only
  mirrors use.

## Onboarding path

<Steps>
<Step>
### Check exchange access

```bash
docker run --rm --entrypoint node ghcr.io/calledado/lean-oracle-publisher:edge apps/publisher/scripts/probe-venues.mjs 20
```

It connects to every market of both committees and prints `OK` or `NONE` for each. Add `--doh` if
your ISP's DNS blocks exchange domains.
</Step>
<Step>
### Generate your key

```bash
docker run --rm ghcr.io/calledado/lean-oracle-publisher:edge keygen
```

Keep the private key secret; send only the public key. For KMS, create an `ECC_SECG_P256K1` key and
share its public key.
</Step>
<Step>
### Run in shadow mode

Shadow mode runs the whole publisher, every exchange connection and every feed's price, but signs
nothing and needs no committee membership. It compares your prices with the committee's signed
updates, tick by tick.

Copy the committee's current config files into your `configs/` folder, and add one line to your
`publisher.json`:

```json
"shadow": { "referenceUrl": "https://64-227-40-35.sslip.io" }
```

```bash
docker run -d --name shadow --restart unless-stopped \
  -v $PWD/operator:/config:ro -v shadow-data:/data -p 127.0.0.1:7701:7701 \
  ghcr.io/calledado/lean-oracle-publisher:edge
curl localhost:7701/health
```

The report lists, for every feed, how many ticks were compared, how many were within the feed's
tolerance, the largest deviation in basis points, and ticks either side missed. Share it when you
ask to join. A healthy operator matches nearly every tick within a few basis points.
</Step>
<Step>
### Join the committee

Your key is added by **rotating** the committee cell. The on-chain script accepts the rotation only
with signatures from a quorum of the current publishers and a proof of possession from every key in
the new set, including yours. Each operator signs on their own machine; a coordinator collects the
files. The full runbook is in [Committee governance](/docs/operate/governance#rotating-keys).

Your part:

```bash
# Review the proposed set: your key should be listed.
docker run --rm -v $PWD:/w -w /w ghcr.io/calledado/lean-oracle-publisher:edge show-set --set next.hex --key publisher.key

# Prove you hold your key.
docker run --rm -v $PWD:/w -w /w ghcr.io/calledado/lean-oracle-publisher:edge sign-pop --next next.hex --key publisher.key > pop-you.json

# Approve each active committee config as a member of the new set.
docker run --rm -v $PWD:/w -w /w ghcr.io/calledado/lean-oracle-publisher:edge \
  sign-config --config configs/v1.json --key publisher.key --set next.hex > approval-you.json
```

Send `pop-you.json` and `approval-you.json` to the coordinator. Once the rotation is on chain, remove
`shadow` from your config, add your peers, and restart the same container: your signatures count from
the next tick.

Keep the same data volume (`shadow-data` above). Shadow mode stores the committee's verified history
there, and a new member needs it to agree with the others on who proposes each tick and on the moving
averages.
</Step>
<Step>
### Approve configs

From then on you review and sign every new committee config version:

```bash
docker run --rm -v $PWD/operator:/config:ro ghcr.io/calledado/lean-oracle-publisher:edge \
  sign-config --config /config/configs/<config.json> --key /config/publisher.key --set /config/publisher-set.hex
```

A version activates at its stated tick once a quorum has signed.
</Step>
</Steps>

## Running it

The operator configuration (`publisher.json`), ports, key options and commands are documented in the
[publisher service README](https://github.com/calledAdo/lean-oracle-v2/tree/main/apps/publisher).
Important rules:

- The `/data` volume holds the double-sign guard. It must persist across restarts and must never be
  shared or copied to another machine.
- **Never run the same key in two places.** Two instances with one key could sign conflicting updates.
- Run with `--restart unless-stopped`: the publisher exits on purpose when the committee rotates, and
  restarts with the new set.
