Proposed (chat only, no code): committees = PublisherSet cells extended with an append-only feed basket; one signed format feeding three products — (1) off-chain signed stream at 250ms–2s (one-round observation bundles, median computed by verifier), (2) on-chain LATEST staggered replica cells (liveness of a cell dep = recency proof; K replicas staggered to avoid dead-cell-dep failures), (3) CHECKPOINT results (two-round quorum-signed, unique per (committee, T) by quorum intersection + double-sign guard) for settlement. Pull mode = consumer attaches an EPHEMERAL result cell output in its own tx (type script verifies), anchored to a live LATEST replica for freshness.
files: llmtimeline/state.md, llmtimeline/sessions/004-2026-09-23-opus.md

Key reasoning: CKB scripts cannot read the including block time; cell deps must be live; updating a shared cell kills pending txs depending on it; each secp256k1 recover ~6.15M cycles against a 3.5B block budget, so verify-once/read-many via cell deps should be the default and pull the exception. One-round median safe because f < q/2 under q=floor(2n/3)+1.
gotchas: supersedes the batch-per-boundary-only proposal earlier in this session. Liveness proves "newest on-chain", not wall-clock freshness; relayer liveness is part of the freshness guarantee.

## Pull-oracle refinement (Hermes-like endpoint, per-price timestamps, historical requests)
status: done
intent: user settled on a pure pull model: publishers continuously sign timestamped prices, an endpoint serves latest / first-at-or-after-T, users submit on-chain; historical use allowed while the signer set is unchanged.
did: proposal (chat only): canonical tick grid per committee (e.g. 1s majors, 2-5s CKB); exactly one quorum-signed update per (committee, tick) via two-round signing with per-tick double-sign guard and real-time-only signing (publishers refuse ticks older than a few seconds); rotating leader = publisher (tick mod n), mirrors are read-only; update = signed header (committee_id, set_index, tick_time_ms, feeds_root) + Merkle leaves per feed (feed_id, price, conf, expo, ema, source_time_ms, publisher_count, flags); on-chain patterns: shared per-feed mutable cell (monotonic), immutable snapshot cell (any tick incl. historical), in-tx verification via common crate.
decisions: proposal only. Current-set-only kept (retired keys must not be able to sign history). Feed basket need not be on-chain (feed_id inside leaf). CKB can enforce "not future-dated" via header dep (update.time <= header.time + skew) and "not older than on-chain state" via monotonic cells, but cannot enforce wall-clock staleness; backdating by a malicious quorum can be bounded by requiring the snapshot cell's creation-block header time <= tick + delta.
gotchas: without canonical ticks, "first price at or after T" is not unique (aggregator can cherry-pick subsets). Missing ticks (no quorum) are permanent by design; consumer policy decides fallback.
next: user decisions (tick periods, Merkle vs flat leaves, whether to keep pool-style boundary cells as snapshot kind); then docs/oracle-v2-design.md.
